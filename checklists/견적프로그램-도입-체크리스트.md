# 견적 프로그램 도입 체크리스트 — 계산 규칙과 단가표부터 금액 표시·유효기간·견적 승인까지

견적 프로그램은 방문자가 옵션과 수량을 고르면 금액을 계산해 보여 주고, 그 내용을 견적서로 남기는 프로그램입니다. 합계를 더하는 기능은 만들기 어렵지 않습니다. 운영을 시작한 뒤 문제가 되는 지점은 따로 있습니다. **페이지에 표시한 금액이 확정 금액인지 예상 금액인지**, **단가를 올린 뒤 예전 견적을 어떤 금액으로 처리하는지**, **견적을 요청한 사람에게 다시 연락할 때 어디부터 광고가 되는지**입니다. 셋 다 프로그램을 만들기 전에 회사 쪽에서 규칙으로 결정해 두셔야 합니다.

이 문서는 견적 프로그램을 맡기기 전에 정리해 두면 견적과 일정이 정확해지는 항목을 모았습니다. 작성한 곳은 [홈피나라](https://hompynara.kr) — 2003년부터 비즈니스 웹사이트와 예약·관리 프로그램을 직접 만들어 왔습니다.

## 1. 어떤 금액을 표시할지 결정한다

가장 먼저 결정할 것은 프로그램이 내놓는 금액의 성격입니다. 입력값만으로 금액이 확정되는 업종이 있고, 현장을 확인해야 금액을 말할 수 있는 업종이 있습니다.

| 방식 | 맞는 경우 | 표시 문구 | 함께 결정할 것 |
| --- | --- | --- | --- |
| 확정 견적 | 인쇄물·제품·렌탈처럼 규격과 수량으로 금액이 확정되는 경우 | 「견적 금액」과 유효기간 | 표시한 금액으로 계약한다는 전제의 단가 관리 |
| 예상 견적 | 인테리어·이사·청소처럼 현장 확인 뒤 금액이 확정되는 경우 | 「예상 금액」과 변동 조건 | 현장 확인 뒤 확정 견적을 발행하는 2단계 절차 |
| 범위 견적 | 입력값이 적은 초기 문의 | 「최소 ○○원 ~ 최대 ○○원」 | 범위를 좁히는 추가 질문 |
| 접수형 견적 | 맞춤 제작·대형 공사처럼 담당자 산출이 필요한 경우 | 「담당자 확인 뒤 ○영업일 안에 발송」 | 담당자 지정과 발송 기한 |

한 회사 안에서 품목마다 방식이 다를 수 있습니다. 규격품은 확정 견적으로, 규격 밖 주문은 접수형으로 넘기는 구성이 보통입니다.

- [ ] 품목별로 네 방식 중 어느 것을 적용할지 결정했는가
- [ ] 예상 금액과 확정 금액을 용어부터 구분해 표시하는가
- [ ] 예상 견적에서 확정 견적으로 넘어가는 절차와 담당자를 결정했는가

## 2. 계산 규칙을 표로 옮긴다

담당자가 머릿속으로 적용하던 규칙을 글과 표로 꺼내는 일이 이 프로그램에서 가장 오래 소요되는 작업입니다. 제작사에 맡기기 전에 아래 유형별로 정리해 두시면 일정이 짧아집니다.

| 규칙 유형 | 예 | 결정할 것 |
| --- | --- | --- |
| 단순 합산 | 기본 금액 + 옵션 금액 | 옵션별 단가와 단위 |
| 조건부 옵션 | A를 선택하면 B는 선택 불가, C는 자동 포함 | 옵션 간 충돌 규칙 |
| 수량 구간 | 100개까지 800원, 101개부터 700원 | 구간 단가를 전체 수량에 적용하는가, 초과분에만 적용하는가 |
| 면적·길이 | ㎡당 단가, 최소 시공 면적 | 최소 금액과 소수점 처리 |
| 지역·거리 | 권역별 출장비, 도서 지역 할증 | 권역 구분과 서비스 불가 지역 |
| 시기 할증 | 성수기, 주말, 긴급 납기 | 적용 기간과 판단 기준일 |
| 할인 | 재구매, 프로모션 코드 | 중복 허용 여부와 할인 한도 |

규칙을 모두 적었다면 **계산 순서**를 결정합니다. 같은 규칙도 순서에 따라 금액이 달라집니다.

| 계산 순서 | 공식 (상품 1,000,000원 · 10% 할인 · 출장비 50,000원) | 결과 |
| --- | --- | --- |
| 출장비를 더한 뒤 할인 | (1,000,000 + 50,000) × 0.9 | 945,000원 |
| 할인한 뒤 출장비를 더함 | 1,000,000 × 0.9 + 50,000 | 950,000원 |

원 단위 처리도 같이 결정합니다. 항목마다 세액을 계산해 더한 값과 합계 금액에 세율을 적용한 값은 원 단위에서 차이가 날 수 있습니다. 세금계산서를 발행하는 프로그램의 계산 방식과 맞춰 두어야 견적 금액과 청구 금액이 일치합니다.

- [ ] 실제로 발행했던 견적 10건 이상을 골라 프로그램 계산 결과와 대조할 준비를 했는가
- [ ] 할인·할증·출장비의 적용 순서와 원 단위 처리 기준을 문서로 결정했는가
- [ ] 수량 초과나 특수 규격처럼 규칙 밖 입력은 금액 대신 「상담 필요」로 전환하는가
- [ ] 최종 금액을 서버에서 다시 계산하는가 (브라우저에서 넘어온 금액을 그대로 저장하면 조작할 수 있습니다)
- [ ] 선택할 수 없는 옵션 조합은 입력 단계에서 막는가

## 3. 단가표 관리 방식을 결정한다

단가가 바뀔 때마다 제작사에 수정을 요청하는 구조라면 금방 프로그램과 실제 단가가 어긋납니다. 회사 담당자가 관리자 페이지에서 직접 고칠 수 있어야 하고, 고친 내용이 지난 견적에 영향을 주지 않아야 합니다.

견적을 저장할 때 단가표를 참조만 해 두면, 단가를 올리는 순간 지난달에 보낸 견적의 금액까지 바뀌어 보입니다. **견적을 발행하는 시점의 품목·단가·할인 규칙을 견적 데이터 안에 함께 저장**해야 합니다. 자동차 점검·정비 견적서 법정 서식이 「부품가는 견적일자 기준입니다」라고 적어 두는 것도 같은 이유입니다.

- [ ] 담당자가 관리자 페이지에서 단가와 할증 규칙을 수정할 수 있는가
- [ ] 단가에 적용 시작일을 지정해 미리 등록할 수 있는가
- [ ] 누가 언제 어떤 단가를 얼마에서 얼마로 바꿨는지 이력이 남는가
- [ ] 발행한 견적이 당시 단가를 그대로 보존하는가
- [ ] 단가 수정 권한과 할인 승인 권한을 나누고 담당자별 할인 한도를 지정했는가
- [ ] 원가·마진·미공개 단가가 페이지 소스나 데이터 응답에 포함되지 않는가 (브라우저에서 계산하는 구조는 단가표 전체가 방문자에게 전달될 수 있습니다)
- [ ] 거래처별 특별 단가가 있다면 로그인한 거래처에만 적용되는가

## 4. 금액 표시 방식을 결정한다

온라인에서 바로 주문·결제까지 이어지는 통신판매라면, 가격을 알리는 「첫 화면」에 필수로 내야 하는 총금액 중 일부만 표시하는 행위가 금지돼 있습니다(전자상거래법 제21조의2 제1항 제1호, 1천만원 이하 과태료 대상). 상품가만 크게 표시하고 필수 배송비·설치비·수수료를 결제 단계에서 처음 보여 주는 방식이 대표적인 사례입니다. 가격이 확정되지 않은 경우의 가격 결정 방법 고지는 같은 법 제13조 제2항에서 확인하시기 바랍니다.

상담을 거쳐 계약하는 업종이라도 표시·광고의 공정화에 관한 법률 제3조는 거짓·과장 표시·광고와 사실을 은폐하거나 축소하는 방법의 기만적인 표시·광고를 금지합니다. 대부분의 고객에게 적용되지 않는 조건의 금액만 크게 표시하는 구성은 검토 대상에 넣으시기 바랍니다.

| 항목 | 권장 표시 | 피할 표시 |
| --- | --- | --- |
| 부가세 | 소비자 대상은 부가세 포함 총액 기본, 사업자 대상은 공급가액·세액·합계 구분 | 합계 옆에 작은 글씨로 「부가세 별도」 |
| 배송·설치·출장비 | 합계에 포함하고, 지역 미입력시 「지역 선택 뒤 확정」 안내 | 마지막 단계에서 처음 표시 |
| 현장 변동 항목 | 어떤 조건에서 어느 항목이 변동되는지 구체적으로 표시 | 「현장 상황에 따라 변동될 수 있음」 한 줄 |
| 최저 금액 | 「○○원부터」와 그 금액이 적용되는 조건을 함께 표시 | 적용 조건 없는 최저 금액 |
| 제외 항목 | 철거·폐기물·사다리차처럼 포함되지 않는 항목을 목록으로 표시 | 표시 없이 현장에서 추가 청구 |
| 할인 전 금액 | 실제 판매 금액을 근거로 표시 | 근거 없는 정상가와 할인율 |

부가세 표시 방식은 법령이 형식을 지정한 내용이 아니라 실무 권장 사항입니다. 다만 부가세가 소비자가 반드시 내야 하는 금액이라면 위 총금액 표시 문제와 이어지므로, 소비자 대상 페이지에서는 포함 금액을 기본값으로 두시기 바랍니다.

- [ ] 합계에 포함되는 비용과 나중에 확정되는 비용을 항목별로 구분했는가
- [ ] 페이지의 합계 금액과 발송되는 견적서의 합계 금액이 항상 일치하는가
- [ ] 금액이 바뀌는 조건을 합계 금액 가까이에 표시하는가
- [ ] 모바일에서 옵션을 바꿀 때 합계 금액이 항상 보이는가

## 5. 견적서 형식과 효력을 결정한다

견적서에 들어갈 항목은 아래 표로 시작하면 빠뜨리는 내용이 적습니다.

| 구분 | 항목 |
| --- | --- |
| 문서 정보 | 견적번호, 버전, 작성일, 유효기간 |
| 공급자 | 상호, 대표자, 사업자등록번호, 주소, 연락처, 담당자 |
| 수신자 | 회사명 또는 이름, 연락처 |
| 금액 | 품목, 규격, 수량, 단가, 공급가액, 세액, 합계 |
| 조건 | 납기, 결제 조건, 포함·제외 범위, 금액 변동 조건 |

제목이 견적서라고 해서 구속력이 전혀 없는 문서가 되는 것은 아닙니다. 실무 해설은 표시 내용, 거래 관행, 당사자 관계를 함께 살펴 판단하고, 목적물과 대금 같은 핵심 조건이 특정되어 상대방이 수락하면 그대로 계약이 되는 형태라면 청약으로 평가될 수 있다고 설명합니다. 청약이라면 임의로 철회할 수 없고(민법 제527조), 승낙 기간을 지정한 청약은 그 기간 안에 승낙 통지를 받지 못하면 효력을 잃습니다(제528조 제1항). 유효기간 문구가 이 효력과 이어지는 셈입니다.

자동으로 발행하는 견적에는 어느 쪽인지 문구로 표시해 두는 편이 안전합니다.

> 참고용 견적: 이 금액은 입력하신 내용을 기준으로 한 예상 금액이며, 담당자 확인 뒤 계약 내용이 확정됩니다.
>
> 확정 견적: 이 견적은 ○○○○년 ○월 ○일까지 유효하며, 기간 안에 승인하시면 위 금액과 조건으로 진행합니다.

문구를 어느 쪽으로 할지는 거래 금액과 업종에 따라 달라지므로 금액이 큰 거래는 변호사에게 확인하시기 바랍니다.

- [ ] 견적번호 체계와 기본 유효기간을 결정했는가
- [ ] 유효기간이 지난 견적은 승인을 막고 재발행으로 안내하는가
- [ ] 견적을 수정하면 새 버전으로 저장하고 이전 버전을 보존하는가
- [ ] 참고용 견적과 확정 견적의 문구를 구분했는가
- [ ] 계산 오류로 잘못 발송한 견적을 누가 어떤 절차로 정정할지 결정했는가
- [ ] 발행 당시 내용을 PDF나 고정된 데이터로 보관하는가

## 6. 연락처 입력 시점과 개인정보를 결정한다

금액을 보여 주는 시점은 영업 방식의 문제이기도 합니다.

| 구성 | 장점 | 단점 |
| --- | --- | --- |
| 금액을 먼저 표시 | 방문자가 입력을 끝까지 진행하기 쉬움 | 연락처 없이 이탈하고, 경쟁사가 단가를 수집하기 쉬움 |
| 금액 범위만 먼저 표시, 상세 견적서는 연락처 입력 뒤 발송 | 금액 정보와 연락처 수집의 균형 | 범위 계산 규칙을 추가로 만들어야 함 |
| 연락처 입력 뒤 금액 표시 | 연락처 확보가 확실하고 단가 노출이 적음 | 입력 부담으로 진행을 멈추는 방문자가 늘 수 있음 |

견적을 요청한 사람의 이름과 연락처는 **계약 체결 과정에서 정보주체의 요청에 따른 조치**에 필요한 범위라면 동의 없이 수집할 수 있습니다(개인정보 보호법 제15조 제1항 제4호). 대신 개인정보보호위원회의 「개인정보 처리 통합 안내서」(2025.7.)는 계약이 체결되지 않으면 수집한 개인정보를 즉시 파기하는 것이 원칙이라고 안내합니다. 파기하지 않으면 3천만원 이하 과태료 대상입니다(제21조 관련). 나중에 다시 영업에 활용할 계획이라면 수집 단계에서 별도의 선택 동의가 필요합니다.

문자·메일 발송 업체나 외부 솔루션에 견적 요청자 정보를 맡기면 개인정보 처리 위탁에 해당할 수 있습니다. 위탁 업무 내용과 수탁자는 홈페이지에 계속 게재해야 합니다(제26조, 시행령 제28조).

- [ ] 견적 계산과 발송에 꼭 필요한 항목만 입력시키는가 (이름·연락처 외 항목은 필요한 이유를 확인)
- [ ] 계약하지 않은 견적을 언제 미체결로 판단해 파기할지 내부 기준을 결정했는가
- [ ] 파기 뒤에도 품목·금액 통계는 개인정보와 분리해 남기는가
- [ ] 홍보 수신 동의를 체크되지 않은 선택 항목으로 분리했는가
- [ ] 발송 업체와 외부 솔루션을 개인정보 처리방침의 위탁 항목에 공개했는가
- [ ] 견적서 열람 주소가 추측할 수 없는 값이고 기간이 지나면 만료되는가
- [ ] 관리자의 견적 목록 엑셀 다운로드를 권한자로 제한했는가
- [ ] 같은 접속에서 반복되는 대량 조회를 제한해 단가 수집에 대비했는가

## 7. 발송과 재연락의 기준을 결정한다

요청한 견적서를 보내는 일과, 견적만 받고 계약하지 않은 사람에게 할인을 제안하는 일은 성격이 다릅니다. 영리 목적의 광고성 정보를 보내려면 받는 사람의 명시적인 사전 동의가 필요하고, 오후 9시부터 다음 날 오전 8시까지는 별도 동의가 필요합니다(전자우편 제외, 정보통신망법 제50조 제1항·제3항). 거래가 끝난 날부터 6개월 안에 같은 종류의 상품을 안내하는 예외가 있지만, 방송미디어통신위원회·한국인터넷진흥원 안내서(2025.12.)는 **단순 문의는 거래관계의 성립으로 볼 수 없다**고 명시합니다. 2026년 10월 2일 시행된 개정으로 위반 시 관련 매출액의 100분의 6 이하 과징금 조항(제50조의9)도 신설됐습니다.

| 메시지 | 판단 | 프로그램에 필요한 것 |
| --- | --- | --- |
| 요청한 견적서 발송 | 방문자의 요청에 응답하는 발송 | 수신 연락처 오류 시 재발송 |
| 유효기간 만료 사실만 알리는 안내 | 내용에 따라 판단. 할인·권유 문구를 넣지 않는 것이 안전 | 문구 고정, 횟수 제한 |
| 「이번 주 계약 시 10% 할인」 같은 제안 | 광고성 정보로 취급 | 사전 동의 확인, (광고) 표기, 수신 거부 안내 |
| 다른 상품·이벤트 안내 | 광고성 정보로 취급 | 사전 동의 확인, 야간 동의 구분 |

견적 알림톡을 보내려면 카카오 비즈니스 채널과 발신프로필을 준비하고 문구 사전심사를 거쳐야 합니다. 심사 전에는 문자나 메일로 발송하도록 구성합니다. 문자 발송 업체에는 회사 발신번호를 먼저 등록해야 합니다.

- [ ] 견적서 발송 경로(메일·문자·알림톡)와 발송 실패 시 대체 경로를 결정했는가
- [ ] 알림톡 채널과 문구 심사 일정을 오픈 일정에 포함했는가
- [ ] 재연락 메시지를 안내성과 광고성으로 나눠 문구를 미리 작성했는가
- [ ] 광고성 메시지는 동의한 사람에게만 발송되도록 막았는가
- [ ] 야간 예약 발송을 야간 동의자에게만 허용하는가
- [ ] 열람 기록에서 메신저 미리보기나 메일 보안 검사의 자동 접속을 구분하는가 (사람이 열지 않았는데 「열람」으로 기록될 수 있습니다)

## 8. 견적 승인과 계약 연결을 결정한다

견적이 승인된 뒤의 절차를 결정해야 개발 범위가 확정됩니다. 승인 자체를 계약으로 볼지, 승인 뒤 계약서와 계약금 단계를 거칠지부터 정리합니다. 계약서 단계를 온라인으로 처리한다면 [전자계약 도입 체크리스트](전자계약-도입-체크리스트.md)를, 계약금을 온라인으로 결제한다면 [PG 연동 도입 체크리스트](PG연동-도입-체크리스트.md)를 함께 확인하시기 바랍니다.

- [ ] 승인 버튼이 계약 성립인지, 다음 단계로 가는 의사 표시인지 문구로 표시했는가
- [ ] 어떤 버전의 견적을 누가 언제 승인했는지 기록하는가
- [ ] 승인 당시 견적 내용을 수정할 수 없는 상태로 보관하는가
- [ ] 승인 뒤 내용이 바뀌면 새 버전을 다시 승인하게 하는가
- [ ] 승인된 견적을 주문·발주·작업 일정 프로그램으로 넘길 항목을 결정했는가
- [ ] 계약 성사와 미성사를 사유와 함께 기록하는가

## 9. 우리 업종에 별도 기준이 있는지 확인한다

일부 업종은 견적서나 가격 표시에 별도 기준이 있습니다. 아래는 대표적인 사례이며, 해당 업종이라면 프로그램 항목을 기준에 맞춰 설계합니다.

| 업종 | 확인할 기준 | 프로그램에 반영할 것 |
| --- | --- | --- |
| 건설·실내건축 공사 | 도급금액, 공사기간 등을 계약서에 분명하게 적고 서명 또는 기명날인한 계약서를 서로 주고받아 보관 (건설산업기본법 제22조 제2항) | 견적 승인에서 끝내지 않고 계약서 단계로 연결, 추가 공사는 변경 내용을 새로 기록 |
| 자동차 점검·정비 | 자동차관리법 시행규칙 별지 제89호의3 서식 (법 제58조 제5항, 시행규칙 제134조 제2항). 교부일부터 1개월 유효, 포함되지 않은 부품 추가 시 소비자 동의, 2부 작성 뒤 1부 교부·1부 1년 보관 | 서식 항목과 부품 구분 코드(A·B·C·D·F) 그대로 구성, 추가 부품 동의 기록 |
| 예식장·결혼준비대행 | 공정거래위원회 「중요한 표시·광고사항 고시」 개정에 따른 가격 정보 공개 (2026년 1월 보도 기준). 기본 서비스, 선택 품목 세부와 요금, 위약금·환급 기준 | 견적 품목과 공개 가격표의 항목을 일치시키고 고시 원문을 확인 |
| 동물병원 | 수술 등 중대진료 전 예상 진료비용 고지 (수의사법 개정, 2023년 1월 시행 보도 기준) | 대상 진료와 예외는 현행 법령에서 확인하고 사전 고지 기록을 보관 |

- [ ] 우리 업종에 견적서 서식이나 가격 표시 기준이 있는지 담당 기관이나 협회에 확인했는가
- [ ] 법정 서식이 있다면 프로그램 출력물이 서식 항목을 모두 포함하는가

## 10. 견적 이후를 측정한다

견적 프로그램은 어느 단계에서 방문자가 멈추는지 데이터가 남는 페이지입니다. 측정 지점을 처음에 넣어 두어야 나중에 옵션 구성과 문구를 고칠 근거가 생깁니다.

| 측정 지점 | 확인할 수 있는 것 |
| --- | --- |
| 계산 시작 | 페이지 방문 대비 계산을 시작한 비율 |
| 옵션 단계별 진행 | 방문자가 멈추는 질문 |
| 금액 확인 | 금액을 본 뒤 이어서 진행하는 비율 |
| 연락처 제출 | 실제 견적 요청 건수 |
| 승인·계약 | 관리자 기록과 연결한 성사 건수 |

- [ ] GA4나 광고 픽셀에 단계별 전환 이벤트를 설정했는가
- [ ] 이름·전화번호 같은 개인정보가 측정 도구로 전달되지 않는가
- [ ] 광고 유입별로 견적 요청과 계약 건수를 비교할 수 있는가

## 11. 기존 엑셀 단가표를 옮긴다

대부분의 회사는 엑셀 단가표에서 시작합니다. 엑셀에는 병합된 셀, 숨겨진 수식, 담당자만 아는 예외가 섞여 있어 그대로 옮길 수 없습니다.

- [ ] 품목마다 고유 코드를 지정하고 단위를 통일했는가
- [ ] 병합 셀과 숨겨진 수식을 풀어 규칙을 글로 적었는가
- [ ] 담당자만 아는 예외 규칙을 인터뷰로 정리했는가
- [ ] 이전 견적 이력을 옮길 범위를 결정했는가 (계약하지 않은 건의 개인정보는 옮기기 전에 파기 대상인지 확인)
- [ ] 오픈 초기에 엑셀 계산과 프로그램 계산을 함께 돌려 대조하는 기간을 두었는가
- [ ] 회사가 직접 고칠 수 있는 범위와 제작사 수정이 필요한 범위를 계약서에 구분했는가

## 12. 도입 전 마지막 확인

- [ ] 품목별 견적 방식과 표시 용어를 결정했는가
- [ ] 계산 순서와 원 단위 처리 기준을 문서로 결정했고 실제 견적과 대조했는가
- [ ] 단가가 바뀌어도 발행한 견적의 금액이 유지되는가
- [ ] 필수 비용을 합계에 포함하고 변동 조건을 금액 가까이에 표시하는가
- [ ] 유효기간과 참고용·확정 견적의 효력 문구를 결정했는가
- [ ] 미계약 견적의 개인정보 파기 기준이 있는가
- [ ] 재연락 메시지를 안내성과 광고성으로 나눠 동의를 확인하는가
- [ ] 승인 기록과 계약 단계 연결을 결정했는가
- [ ] 업종별 서식과 가격 표시 기준을 확인했는가

---

법령과 고시는 개정될 수 있고, 이 문서의 확인 수준은 항목마다 다릅니다. 개인정보 보호법, 정보통신망법, 전자상거래 등에서의 소비자보호에 관한 법률의 내용은 2026년 9~10월에 현행 조문을 대조해 작성한 이 저장소의 다른 체크리스트를 기준으로 삼았습니다. 민법, 건설산업기본법, 표시·광고의 공정화에 관한 법률은 공개된 법령 페이지에서 조문을 읽었으며 이번 작성 시점의 현행본과 다시 대조하지 못했습니다. 자동차 점검·정비 견적서는 2023년 6월 9일 개정 서식을 기준으로 했고, 결혼서비스 가격 공개와 수의사법의 고지 의무는 언론 보도를 기준으로 적었습니다. 견적서의 청약 해당 여부와 부가세 표시 방식은 실무 기준이며, 조문이나 판례로 확정해 드리는 내용이 아닙니다. 실제 적용 전에는 [국가법령정보센터](https://www.law.go.kr)에서 현행 조문을 확인하시고, 금액이 큰 거래는 변호사나 세무사에게 확인하시기 바랍니다.

옵션 선택에 따른 실시간 계산, 수량·지역별 규칙, 산출 내역 발송, 관리자 견적 저장을 한 곳에서 처리하는 구성은 [견적 프로그램 제작과 온라인 자동 견적](https://hompynara.kr/program/auto-estimate.php)에 정리돼 있습니다. 구축 문의는 [홈피나라 상담](https://hompynara.kr/inquiry.php)으로 주십시오.
