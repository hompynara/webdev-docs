# 렌트카 홈페이지·예약 시스템 도입 체크리스트 — 차량 단위 재고부터 면허 확인·반납 정산까지

렌트카 홈페이지에 예약을 붙이려고 알아보면 숙박과 비슷해 보입니다. 날짜를 고르고 차를 고르고 결제하면 끝인 것 같습니다. 실제로 갈리는 지점은 **같은 차종을 판 것인지 그 차 한 대를 판 것인지**, 그리고 **반납한 뒤에 생기는 돈을 무엇으로 정산하는가**입니다. 둘 다 개발 이전에 대여사업자가 먼저 정해 두셔야 하는 것들입니다.

이 문서는 예약 시스템을 맡기기 전에 정리해 두면 견적과 일정이 정확해지는 항목을 모았습니다. 작성한 곳은 [홈피나라](https://hompynara.kr) — 2003년부터 비즈니스 웹사이트와 예약·관리 프로그램을 직접 만들어 왔습니다.

## 1. 등록 상태와 대여약관을 먼저 확인한다

렌트카는 등록 사업입니다. 「여객자동차 운수사업법」 시행규칙 별표 4가 자동차대여사업의 등록기준을 정하고 있고, 영업구역이 전국이면 **자동차 50대 이상**에 차고지·사무실·영업소를 갖춰야 합니다. 주사무소와 영업소가 모두 하나의 시·군에 있고 그 지역에서만 영업한다면 50대 미만 범위에서 **해당 지방자치단체 조례가 정하는 대수**를 따릅니다.

홈페이지와 직접 걸리는 것은 그다음입니다. 같은 법 **제31조 제1항**은 자동차대여사업자가 **대여약관을 정해 사업 시작 전까지 시·도지사에게 신고**하도록 하고, 약관을 바꿀 때도 다시 신고하게 합니다. 즉 홈페이지에 올리는 약관은 마음대로 고쳐 쓰는 문서가 아니라 **신고한 내용과 같아야 하는 문서**입니다.

- [ ] 우리 영업구역이 전국인지 특정 시·군인지 확인했는가
- [ ] 홈페이지에 게시할 대여약관이 시·도에 신고한 약관과 같은 내용인가
- [ ] 약관을 홈페이지에서 수정할 수 있게 만든다면 신고 절차를 누가 챙기는가
- [ ] 공정거래위원회 자동차대여 표준약관과 우리 약관을 대조해 봤는가

## 2. 차량을 어떤 단위로 파는지 정한다

여기서 시스템 구조가 갈립니다. 숙박은 "객실 × 날짜"지만 렌트카는 **차종으로 팔고 차량으로 배차**하는 경우가 많습니다.

| 판매 단위 | 어떤 사업장에 맞나 | 시스템에서 생기는 일 |
| --- | --- | --- |
| 차종 단위 | 같은 차종을 여러 대 보유 | 재고는 대수로 세고, 배차는 출고 시점에 정한다 |
| 개별 차량 단위 | 수입차·특수차처럼 대수가 적음 | 차량 하나가 곧 재고다. 번호판까지 예약에 붙는다 |
| 혼합 | 대중 차종은 차종, 고급 차종은 개별 | 두 규칙이 한 달력 안에서 동시에 돌아야 한다 |

- [ ] 차종 단위로 팔 것인가 개별 차량 단위로 팔 것인가
- [ ] 차종별 보유 대수와 등급 분류를 표로 만들었는가
- [ ] 지점이 여럿이라면 차량이 지점에 묶이는가, 지점 간 이동이 가능한가
- [ ] 정비·사고·검사로 빠지는 차량을 관리자에서 재고에서 뺄 수 있어야 하는가

> 대수로만 세면 예약은 받았는데 출고 당일 배차할 차가 없는 일이 생깁니다. **정비 입고와 사고 수리를 재고에서 빼는 화면이 없으면 반드시 그렇게 됩니다.** 예약 달력과 차량 상태가 같은 데이터를 봐야 합니다.

## 3. 요금 계산 규칙을 먼저 문서로 만든다

렌트카 요금은 숙박보다 규칙이 많습니다. 개발에 들어가기 전에 이 표가 채워져 있어야 견적이 정확해집니다.

| 확인 항목 | 왜 물어보는가 |
| --- | --- |
| 기본 단위가 24시간인가 일(日) 단위인가 | 오후 3시 대여·다음날 오전 10시 반납의 요금이 달라집니다 |
| 시간 초과분을 어떻게 계산하는가 | 시간당 요금인지 일 요금의 몇 %인지 정해야 합니다 |
| 성수기·주말 요금이 다른가 | 요일과 기간 규칙을 달력에 얹어야 합니다 |
| 장기 대여 할인 구간이 있는가 | 7일·30일 구간에서 단가가 꺾입니다 |
| 편도 반납을 받는가 | 지점이 다르면 회수 비용이 붙습니다 |
| 보험료가 요금에 포함인가 별도인가 | 화면 표시 금액의 정의가 달라집니다 |

- [ ] 기본 요금 단위와 초과 요금 규칙을 정했는가
- [ ] 성수기 달력과 장기 할인 구간을 표로 만들었는가
- [ ] 편도 반납 수수료와 가능한 지점 조합을 정리했는가
- [ ] 화면에 표시하는 금액에 무엇이 포함되는지 한 문장으로 쓸 수 있는가

## 4. 중복 예약을 어디서 막는지 확인한다

대부분의 사고는 **결제 직전 몇 초** 사이에 생깁니다. 두 사람이 같은 차를 동시에 붙잡고 있을 때 먼저 접수된 쪽만 확정되어야 하는데, 화면에서 버튼을 막는 것으로는 부족합니다. 데이터베이스 단계에서 차단해 뒤에 온 요청이 거부되어야 합니다.

렌트카에는 숙박에 없는 조건이 하나 더 있습니다. **반납과 다음 대여 사이에 세차·점검 시간이 필요**합니다. 이 간격을 재고 규칙에 넣지 않으면 오전에 반납된 차가 30분 뒤 다시 나가는 예약이 잡힙니다.

- [ ] 차량이 점유되는 시점이 예약 신청인가 결제 완료인가
- [ ] 결제 진행 중인 건을 몇 분간 붙잡아 두는가 (미결제 시 자동 해제)
- [ ] 반납과 다음 대여 사이 준비 시간을 몇 분으로 둘 것인가
- [ ] 관리자가 수동으로 잠근 기간(정비·장기 계약)이 달력에 반영되는가

## 5. 운전자격 확인을 예약 화면 어디에 둘지 정한다

렌트카가 다른 예약 업종과 결정적으로 다른 지점입니다. 차종마다 필요한 면허가 다릅니다. 「도로교통법」 제80조 제2항과 시행규칙 제53조·별표 18이 운전할 수 있는 차의 종류를 면허별로 정하고 있어서, 승합차는 승차정원에 따라 1종 대형·1종 보통·2종 보통이 갈립니다.

**여기서 개인정보 문제가 같이 붙습니다.** 운전면허번호는 「개인정보 보호법」 제24조 제1항과 같은 법 시행령 제19조가 정하는 **고유식별정보**입니다. 주민등록번호·여권번호·외국인등록번호와 같은 등급입니다. 다른 개인정보 수집 동의와 **별도로 동의를 받아야** 처리할 수 있습니다. 예약 폼에 면허번호 칸을 그냥 하나 더 만들면 안 되는 이유가 이것입니다.

- [ ] 예약 단계에서 면허를 확인하는가, 출고 현장에서 확인하는가
- [ ] 면허번호를 받는다면 별도 동의 항목이 분리되어 있는가
- [ ] 면허 사본 이미지를 보관한다면 언제 파기하는지 정해져 있는가
- [ ] 차종별로 필요한 면허 종류가 예약 화면에 표시되는가
- [ ] 나이·운전경력 제한(보험 조건)을 예약 단계에서 거르는가
- [ ] 외국인 이용자의 국제운전면허 확인 절차가 있는가

> 예약 확인·변경 알림과 **홍보·이벤트 안내는 성격이 다릅니다.** 후자는 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 제50조에 따라 사전 수신 동의가 따로 필요하고, 오후 9시부터 다음 날 오전 8시까지는 야간 발송 동의를 또 받아야 합니다. 예약 알림 동의로 프로모션 문자를 보내면 안 됩니다.

## 6. 예약금과 취소 위약금을 기준대로 계산한다

임의로 정하면 안 되는 영역입니다. 공정거래위원회 **소비자분쟁해결기준**의 자동차대여업 항목이 예약금 상한과 취소 환급을 정하고 있습니다.

| 상황 | 처리 |
| --- | --- |
| 예약금 청구 | 대여예정 요금의 **10% 범위** 안에서 |
| 사용개시 24시간 전까지 취소 | 예약금 **전액 환급** |
| 사용개시 24시간 이내 취소 | 대여예정 요금의 **10% 공제** 후 환급 |
| 사업자 사정으로 취소 | 예약금에 대여예정 요금의 **10%를 가산**해 환급 |
| 대여기간 중 해지 (고객 사정) | 잔여기간 요금의 10% 공제 후 환급 |
| 대여기간 중 해지 (사업자 사정) | 잔여기간 요금의 10% 가산 후 환급 |

기준이 되는 시각은 결제일이 아니라 **사용개시 일시**입니다. 시스템이 취소 시점을 계산할 때 이 두 시각의 차이를 보게 해야 합니다. 그리고 이 기준은 개별 약관이 있으면 약관이 먼저 적용되므로, **우리 약관이 이 기준보다 고객에게 불리하지 않은지**를 먼저 확인해야 합니다.

- [ ] 위약금 계산 기준 시각이 사용개시 일시로 되어 있는가
- [ ] 예약금 비율이 대여예정 요금의 10%를 넘지 않는가
- [ ] 사업자 사정으로 취소할 때의 가산 환급 절차가 정해져 있는가
- [ ] 환불이 결제 수단별로 며칠 안에 이루어지는지 안내하는가
- [ ] 태풍·폭설 등으로 운행이 어려울 때의 처리 기준이 약관에 있는가

## 7. 보험·면책금·휴차료를 화면에서 분리해 쓴다

문의 전화가 가장 많이 오는 자리이고, 분쟁도 여기서 생깁니다. 세 가지는 서로 다른 돈인데 화면에 뭉쳐 놓으면 고객이 같은 것으로 읽습니다.

자기차량손해 보상은 **가입 여부·보상 한도·면책금**이 각각 다릅니다. 사고가 나면 고객이 면책금을 내고, 차가 수리에 들어가 있는 동안 영업하지 못한 손해를 **휴차료**로 따로 청구합니다. 공정거래위원회는 2021년 11월 자동차대여 표준약관을 개정하면서 **휴차 손해 산정 기준을 명확히 하고 연료 초과 반납분 정산 조항을 신설**했습니다.

- [ ] 자차보험 가입이 선택인가 필수인가, 화면에서 고를 수 있는가
- [ ] 면책금 금액과 보상 한도가 예약 화면에 표시되는가
- [ ] 휴차료 산정 방식이 약관과 홈페이지에 같은 내용으로 적혀 있는가
- [ ] 보상에서 빠지는 항목(음주·무면허·목적 외 사용)을 명시했는가
- [ ] 사고 접수 연락처와 절차가 예약 완료 안내에 들어가는가

## 8. 반납 뒤에 생기는 정산을 미리 설계한다

렌트카는 **반납 시점에 거래가 끝나지 않습니다.** 이 절을 빼고 만들면 반년 뒤에 관리자 화면을 다시 만들게 됩니다.

| 반납 후 발생 항목 | 언제 확정되나 |
| --- | --- |
| 연료 부족·초과분 | 반납 즉시 |
| 반납 지연 요금 | 반납 즉시 |
| 하이패스 통행료 | 며칠 뒤 청구서로 |
| 주정차 위반 과태료 | 몇 주 뒤 고지서로 |
| 수리비·휴차료 | 수리 완료 후 |

과태료와 통행료는 차량 소유자인 대여사업자에게 먼저 옵니다. 그것을 임차인에게 넘기려면 **대여 기간과 운전자를 특정할 수 있는 기록**이 남아 있어야 합니다. 예약 데이터를 언제까지 보관할지가 여기서 정해집니다.

- [ ] 반납 후 추가 청구를 어떤 수단으로 받을 것인가 (카드 재승인·계좌·별도 결제 링크)
- [ ] 대여 기간과 운전자 정보를 언제까지 보관하는가
- [ ] 통행료·과태료가 뒤늦게 왔을 때 어느 예약 건에 붙이는지 관리자에서 찾을 수 있는가
- [ ] 연료 정산 기준(만유 반납·동일 수준 반납)을 약관과 화면에 같이 적었는가

## 9. 홈페이지 문구가 법에 걸리는 자리를 확인한다

렌트카 홈페이지에서 실제로 문제가 되는 문구가 있습니다. 「여객자동차 운수사업법」 **제34조**는 임차인이 대여 차량을 **유상 운송에 쓰거나 다시 남에게 빌려주는 것**을 금지하고, 누구든 그것을 **알선하는 것**도 금지합니다. 같은 조 제2항은 **임차인에게 운전자를 알선하는 것**도 원칙적으로 금지합니다.

예외가 좁게 열려 있습니다. 관광을 목적으로 **승차정원 11인승 이상 15인승 이하** 승합자동차를 빌리는 경우에, 대여시간이 **6시간 이상**이거나 대여·반납 장소가 **공항 또는 항만**인 때로 한정합니다.

그래서 홈페이지에 "기사 포함 대여", "운전기사 연결"처럼 적으면 그 조건 밖에서는 알선 금지에 걸립니다. **예약 화면의 옵션 하나로 만들어 두면 조건과 무관하게 팔리게 됩니다.**

- [ ] 기사 알선을 상품으로 파는가, 판다면 정원·시간·장소 조건을 시스템이 거르는가
- [ ] 차량 소개 문구에 재대여·영업용 사용을 권하는 표현이 없는가
- [ ] 장기 렌트와 리스를 홈페이지에서 구분해 설명하고 있는가

## 10. 도입 전 마지막 확인

- [ ] 영업구역과 등록 대수를 확인하고 대여약관 신고 상태를 점검했는가
- [ ] 차종 단위로 팔지 개별 차량 단위로 팔지 정했는가
