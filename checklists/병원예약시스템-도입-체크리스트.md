# 병원 예약 시스템 도입 체크리스트 — 본인확인 의무화부터 민감정보 동의까지

병원 홈페이지에 예약 기능을 붙이는 일은 펜션이나 식당 예약과 겉모습이 비슷합니다. 날짜를 고르고 시간을 고르고 연락처를 남기는 화면까지는 같습니다. **다른 것은 그 화면이 받는 정보가 법적으로 다른 취급을 받는다는 점**입니다. 환자가 "허리가 아파서"라고 한 줄 적는 순간 그것은 일반 개인정보가 아니라 민감정보가 됩니다.

여기에 2024년부터 진료 전 본인확인이 의무가 되면서 접수 흐름 자체가 바뀌었습니다. 예약 시스템을 만들 때 이 변화를 반영하지 않으면 화면은 완성돼도 창구 업무는 그대로 남습니다.

이 문서는 병원 예약 시스템을 맡기기 전에 정리해 두면 견적과 일정이 정확해지는 항목을 모았습니다. 작성한 곳은 [홈피나라](https://hompynara.kr) — 2003년부터 비즈니스 웹사이트와 예약·관리 프로그램을 직접 만들어 왔습니다.

## 1. 예약 화면에서 받을 정보의 경계를 먼저 긋는다

**건강에 관한 정보는 민감정보입니다.** 개인정보보호법 제23조 제1항은 건강·성생활 등에 관한 정보를 민감정보로 정하고 원칙적으로 처리를 금지합니다. 처리하려면 같은 항 단서에 따라 **다른 개인정보 동의와 별도로** 동의를 받아야 합니다. 예약 화면 하단에 동의 체크박스 하나만 두고 넘어가면 이 요건을 채우지 못합니다.

| 예약 화면에서 받는 것 | 법적 성격 | 필요한 동의 |
| --- | --- | --- |
| 이름·연락처·생년월일 | 일반 개인정보 | 수집·이용 동의 |
| 진료과 선택 | 사안에 따라 다름 | 아래 설명 참고 |
| 증상·통증 부위·기왕력 메모 | **민감정보** | **별도 동의** |
| 초진·재진 구분 | 일반 개인정보 | 수집·이용 동의 |

진료과는 판단이 갈립니다. 내과·정형외과처럼 범위가 넓은 과는 그 자체로 건강 상태를 특정하기 어렵지만, 특정 질환만 다루는 과나 클리닉명을 고르게 하면 사실상 병력을 드러내는 정보가 됩니다. **애매하면 민감정보로 보고 별도 동의를 받는 편이 안전합니다.**

- [ ] 예약 화면에서 증상·메모를 받을 것인지 정했는가
- [ ] 받는다면 일반 동의와 **구분된** 민감정보 동의 항목을 두었는가
- [ ] 동의를 거부해도 예약 자체는 가능하게 설계했는가 (필수·선택 구분)
- [ ] 받지 않기로 했다면 상담이 필요한 환자를 어떤 경로로 안내할 것인가

> 가장 단순한 해법은 **예약 단계에서 증상을 아예 받지 않는 것**입니다. 날짜·시간·진료과까지만 받고 상세한 내용은 내원 후 문진표로 넘기면 민감정보 처리 자체가 줄어듭니다. 온라인 문진이 꼭 필요한 경우에만 별도 동의를 설계하십시오.

## 2. 2024년부터 바뀐 본인확인 의무를 반영한다

**2024년 5월 20일부터 요양기관은 건강보험을 적용해 진료할 때 신분증 등으로 본인 여부와 자격을 확인해야 합니다**(국민건강보험법 제12조 제4항). 확인하지 않고 요양급여를 실시하면 공단이 그 비용을 요양기관에서 환수할 수 있습니다.

인정되는 것은 주민등록증·운전면허증·외국인등록증처럼 **사진이 붙어 있고 주민등록번호(또는 외국인등록번호)가 적힌 신분증**이며, 모바일 건강보험증과 모바일 신분증도 됩니다. **사본이나 신분증을 찍은 사진은 인정되지 않습니다.** 응급환자나 처방전으로 약국에서 약을 받는 경우 등은 예외입니다.

여기서 예약 시스템이 할 수 있는 일과 할 수 없는 일이 갈립니다. **본인확인은 창구에서 실물로 해야 하므로 온라인 예약이 대신할 수 없습니다.** 다만 환자가 신분증을 안 가져와서 되돌아가는 일은 줄일 수 있습니다.

- [ ] 예약 완료 화면과 알림 문자에 "내원 시 신분증 지참" 안내를 넣었는가
- [ ] 모바일 건강보험증 발급 방법을 안내할 것인가
- [ ] 예외 대상(응급·처방전 수령 등)을 창구에서 어떻게 구분할 것인가
- [ ] 재진 환자에게도 같은 안내가 나가는가 (6개월 내 확인 이력 처리 방침)

> 신분증 미지참으로 인한 접수 지연이 예약 시간표를 밀리게 만듭니다. **예약 하루 전 알림 문자에 지참 안내를 한 줄 넣는 것만으로 창구 실랑이가 눈에 띄게 줄어듭니다.**

## 3. 진료과·의료진·시간 단위를 확정한다

예약 시스템의 복잡도는 화면이 아니라 **시간표 규칙**에서 결정됩니다. 이걸 정하지 않고 개발에 들어가면 "이 경우는 어떻게 되나요"가 끝없이 나옵니다.

| 확인 항목 | 왜 물어보는가 |
| --- | --- |
| 진료과별로 예약을 받는가, 의료진별로 받는가 | 예약 단위가 달라집니다 |
| 의사마다 진료 요일·시간이 다른가 | 개인별 근무표를 시스템에 넣어야 합니다 |
| 진료 1건에 배정하는 시간이 과마다 다른가 | 슬롯 길이가 달라집니다 |
| 초진과 재진의 소요 시간이 다른가 | 같은 슬롯에 다른 인원이 들어갑니다 |
| 검사·처치가 붙는 예약이 있는가 | 장비·처치실 자원도 함께 잡아야 합니다 |
| 휴진·학회·휴가를 누가 언제 입력하는가 | 관리자 운영 부담과 직결됩니다 |

- [ ] 의료진별 진료 시간표를 요일 단위 표로 만들어봤는가
- [ ] 진료 유형별 소요 시간(분)을 정했는가
- [ ] 하루에 받을 수 있는 최대 예약 수를 정했는가
- [ ] 당일 예약을 받을 것인가, 몇 시간 전까지만 받을 것인가
- [ ] 공휴일·임시 휴진을 관리자에서 막는 방법이 있는가

## 4. 예약 부도(노쇼)를 어떻게 다룰지 정한다

병원 예약에서 가장 자주 나오는 운영 문제입니다. 숙박이나 공연과 달리 **진료 예약은 선결제가 일반적이지 않아** 위약금을 물리기 어렵습니다.

현실적인 대응은 세 가지입니다. 예약 전날과 당일 알림을 보내 잊지 않게 하는 것, 취소를 쉽게 만들어 빈자리를 다시 팔 수 있게 하는 것, 그리고 반복 노쇼 환자를 기록해 두는 것입니다. **취소를 어렵게 만들면 노쇼가 줄어드는 것이 아니라 연락 없는 노쇼로 바뀝니다.**

- [ ] 예약 알림을 언제 몇 번 보낼 것인가 (전날·당일 아침 등)
- [ ] 환자가 스스로 취소·변경할 수 있는가, 전화로만 가능한가
- [ ] 취소된 자리를 대기 환자에게 알릴 것인가
- [ ] 반복 노쇼 이력을 관리자에서 볼 수 있게 할 것인가
- [ ] 노쇼가 잦은 시간대를 통계로 확인할 수 있는가

## 5. 비급여 가격은 홈페이지에 표시해야 한다

**인터넷 홈페이지를 운영하는 의료기관은 비급여 진료비용을 홈페이지에 따로 표시해야 합니다**(의료법 제45조, 같은 법 시행규칙 제42조의2). 접수창구에 책자를 비치하는 것과 **별개의 의무**입니다. 예약 시스템을 새로 붙이면서 홈페이지를 손보는 김에 이 부분이 갖춰져 있는지 함께 확인하는 편이 낫습니다.

보건복지부장관이 고시로 정한 비급여 항목은 **진료 전에 환자에게 항목과 가격을 직접 설명**해야 합니다. 이 설명 의무는 화면으로 대체되지 않습니다.

- [ ] 홈페이지에 비급여 항목·가격 페이지가 있는가
- [ ] 그 내용이 접수창구 비치본과 같은가 (가격 개정 시 양쪽을 함께 고치는가)
- [ ] 가격이 바뀌었을 때 누가 홈페이지를 수정하는가
- [ ] 예약 화면에서 비급여 시술을 고르게 한다면 가격이 함께 보이는가

> 비급여 페이지를 이미지 한 장으로 올려두면 검색에도 안 잡히고 수정할 때마다 디자인을 다시 해야 합니다. **표로 만들어 관리자에서 고칠 수 있게** 해 두는 편이 낫습니다.

## 6. 홈페이지 문구가 의료광고가 된다

병원 홈페이지의 소개 문구는 의료광고입니다. 의료법 제56조는 치료효과를 보장하는 표현, 다른 의료기관과 비교하는 표현, 환자의 치료경험담을 이용한 광고 등을 금지합니다. **예약 페이지의 안내 문구나 후기란도 같은 기준을 적용받습니다.**

사전심의는 조금 다릅니다. 의료법 제57조의 사전심의 대상 매체는 신문·인터넷신문·정기간행물, 현수막·벽보·전단·교통수단 광고, 그리고 대통령령이 정하는 매체입니다. **의료기관 자체 홈페이지는 이용자 규모 기준을 넘지 않는 한 사전심의 대상이 아닙니다.** 다만 심의 대상이 아니라는 것이 제56조 금지사항을 지키지 않아도 된다는 뜻은 아닙니다.

- [ ] 예약 페이지 안내 문구에 치료효과를 단정하는 표현이 없는가
- [ ] 환자 후기·치료 전후 사진을 예약 화면 주변에 노출하고 있지 않은가
- [ ] 이벤트·할인 문구를 쓴다면 의료법 위반 소지를 검토했는가
- [ ] 홈페이지 문구를 누가 최종 확인하는가

## 7. 알림 문자와 개인정보 보관

- [ ] 예약 확인·변경·취소 알림을 문자로 보낼 것인가, 알림톡으로 보낼 것인가
- [ ] 알림 발송에 필요한 수신 동의를 예약 화면에서 받는가
- [ ] 예약 정보를 언제까지 보관하고 언제 파기하는가
- [ ] 진료기록과 예약기록을 분리해서 관리하는가
- [ ] 관리자 계정을 여러 명이 쓴다면 누가 무엇까지 볼 수 있는가
- [ ] 퇴사자 계정을 정리하는 절차가 있는가

> 진료 안내 목적의 알림과 **홍보·이벤트 안내는 성격이 다릅니다.** 후자는 정보통신망법 제50조에 따라 사전 수신 동의가 별도로 필요하고, 오후 9시부터 다음 날 오전 8시까지는 야간 발송 동의를 또 받아야 합니다. 예약 알림 동의로 홍보 문자를 보내면 안 됩니다.

## 8. 도입 전 마지막 확인

- [ ] 예약 화면에서 증상·메모를 받을지 정하고, 받는다면 별도 동의를 설계했는가
- [ ] 신분증 지참 안내를 예약 완료 화면과 알림에 넣었는가
- [ ] 의료진별 시간표와 진료 유형별 소요 시간을 표로 만들었는가
- [ ] 노쇼 대응 방식(알림·취소 정책·이력 관리)을 정했는가
- [ ] 홈페이지 비급여 가격 표시가 최신 상태인가
- [ ] 예약 페이지 문구를 의료광고 기준으로 검토했는가
- [ ] 관리자를 누가 맡고 예약 확인을 하루 몇 번 할 것인가
