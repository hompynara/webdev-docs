# 숙박·펜션 실시간 예약 시스템 도입 체크리스트 — 중복 예약 방지부터 환불 규정까지

펜션이나 독채 숙소에 실시간 예약을 붙이려고 알아보면 대부분 "달력에서 날짜 고르고 결제"까지는 다 비슷해 보입니다. 실제로 갈리는 지점은 화면이 아니라 **같은 방이 두 번 팔렸을 때 무엇이 기록에 남는가**, 그리고 **취소가 들어왔을 때 얼마를 돌려줘야 하는가**입니다. 이 둘은 개발 이전에 사장님이 먼저 정해 두셔야 하는 것들입니다.

이 문서는 예약 시스템을 맡기기 전에 정리해 두면 견적과 일정이 정확해지는 항목을 모았습니다. 작성한 곳은 [홈피나라](https://hompynara.kr) — 2003년부터 비즈니스 웹사이트와 예약·관리 프로그램을 직접 만들어 왔습니다.

## 1. 우리 숙소가 법적으로 무엇인지부터 확정한다

상호에 "펜션"이 붙어 있어도 법적 분류는 셋으로 갈립니다. **여기가 정해져야 홈페이지에 무엇을 표시해야 하는지가 정해집니다.**

| 분류 | 근거 법령 | 신고·등록처 |
| --- | --- | --- |
| 숙박업(일반·생활) | 공중위생관리법 | 시장·군수·구청장 신고 |
| 농어촌민박 | 농어촌정비법 제86조 | 시장·군수·구청장 신고 |
| 관광펜션업 | 관광진흥법 | 시·도지사 지정 |

농어촌민박은 요건이 구체적입니다. **농어촌·준농어촌 지역 주민이 본인이 거주하는 단독주택(다가구 포함)에서 운영**해야 하고, 해당 시·군·구에 **6개월 이상 계속 거주**해야 하며, **주택 연면적 230㎡ 미만**이어야 합니다(농어촌정비법 제86조 및 시행규칙). 상호가 "○○펜션"이어도 이 신고로 운영 중이라면 법적으로는 농어촌민박입니다.

- [ ] 우리 숙소가 위 셋 중 무엇으로 신고·등록되어 있는지 확인했는가
- [ ] 신고확인증(또는 지정서)의 상호와 홈페이지 상호가 같은가
- [ ] 객실 수와 면적이 신고 내용과 일치하는가

## 2. 객실과 요금 구조를 먼저 그린다

요금표가 정리되지 않은 채로 개발에 들어가면 나중에 "이 경우는 어떻게 되나요"가 계속 나옵니다.

| 확인 항목 | 왜 물어보는가 |
| --- | --- |
| 객실을 개별로 파는가, 독채 통째로 파는가 | 재고 단위가 방인지 동인지 달라집니다 |
| 기준 인원과 최대 인원이 있는가 | 인원 추가 요금을 자동 계산해야 합니다 |
| 주중·주말·공휴일 요금이 다른가 | 요일별 규칙을 달력에 얹어야 합니다 |
| 성수기 기간을 따로 정해 두었는가 | 3번·4번에서 다시 쓰입니다 |
| 연박 할인이나 최소 숙박일이 있는가 | 성수기 2박 이상 같은 조건 |
| 입실·퇴실 시각이 객실마다 다른가 | 청소 시간 확보와 직결됩니다 |

- [ ] 객실 목록을 이름·기준인원·최대인원·기본요금까지 채운 표로 만들었는가
- [ ] 주중/주말/성수기 요금을 날짜 기준으로 적어봤는가
- [ ] 인원 추가·조식·바비큐 같은 부가 요금을 목록으로 뽑았는가

## 3. 중복 예약을 막는 방식을 확인한다

실시간 예약에서 가장 비싼 사고입니다. 같은 방이 두 번 팔리면 환불로 끝나지 않고 후기와 평판으로 남습니다.

문제는 대부분 **결제 직전 몇 초** 사이에 생깁니다. 두 사람이 같은 날짜를 동시에 붙잡고 있을 때 먼저 결제한 쪽만 확정되어야 하는데, 이걸 화면에서 막는 것으로는 부족합니다. 데이터베이스 단계에서 잠금을 걸어야 합니다.

- [ ] 결제 완료 시점에 객실이 점유되는가, 아니면 예약 신청 시점인가
- [ ] 결제 진행 중인 건을 몇 분간 붙잡아 두는가 (미결제 시 자동 해제)
- [ ] 사장님이 관리자에서 수동으로 막아둔 날짜(개인 사용·수리)가 반영되는가
- [ ] 외부 채널에서 팔린 건이 홈페이지 달력에도 즉시 반영되는가 (6번 참고)

> 견적 요청 시 **"동시 접속 상황에서 중복 예약을 어떻게 막는지"를 문서로 요구**하십시오. 답이 "화면에서 막습니다" 수준이면 다시 물어보셔야 합니다.

## 4. 취소·환불 규칙을 시스템에 넣는다

숙박은 취소 분쟁이 가장 잦은 업종입니다. **약관에 환불 규정을 명확히 적어두지 않으면 소비자분쟁해결기준이 판단 근거가 됩니다.**

2024년 12월 19일 시행된 개정 기준은 **계약 후 24시간 이내 취소를 위약금 없이 환급**하도록 정하고 있습니다(단, 사용 예정일 0시 이전까지). 개정 전에는 "계약 당일 취소"였는데, 오전에 예약하든 밤에 예약하든 자정까지만 인정되어 형평이 맞지 않는다는 지적에 따라 바뀐 것입니다.

성수기·비수기 구분은 **사업자가 약관에 정한 기간이 우선**이고, 약관에 없으면 공정거래위원회 기준(여름 7월 15일~8월 24일, 겨울 12월 20일~2월 20일)이 적용됩니다. 우리 숙소의 성수기가 그와 다르다면 **약관에 적어두지 않는 한 인정되지 않습니다.**

- [ ] 성수기·비수기 기간을 약관에 날짜로 명시했는가
- [ ] 취소 시점별 환급률을 표로 정리했는가 (며칠 전 / 당일 / 노쇼)
- [ ] 계약 후 24시간 이내 취소를 시스템이 자동으로 구분하는가
- [ ] 환불 규정을 예약 화면에서 결제 전에 보여주는가
- [ ] 환급 계산을 사람이 하는가, 시스템이 자동으로 하는가

> 위약금 계산을 사람이 하면 성수기·주중·예약 시각이 겹칠 때마다 실수가 납니다. **규칙을 관리자에서 설정하고 시스템이 금액을 제시하도록** 설계하는 편이 분쟁을 줄입니다.

## 5. 결제 방식과 준비 기간

- [ ] 온라인 결제를 받을 것인가, 계좌이체 입금 확인 방식으로 갈 것인가
- [ ] 예약금(일부)만 받을 것인가, 전액을 받을 것인가
- [ ] 현장 결제 잔금이 있다면 그 금액이 예약서에 표시되는가
- [ ] 취소 시 부분 환불을 PG에서 처리할 수 있는 구조인가

> ⚠️ **PG(결제대행) 가맹 계약은 사업자 명의로 직접 체결해야 하고 심사 기간이 별도로 걸립니다.** 제작사가 대신 열어드릴 수 없는 부분이라, 오픈 일정을 잡을 때 이 기간을 반드시 포함해야 합니다. 심사가 늦어지면 **먼저 계좌이체 방식으로 열고 승인 후 전환**하는 방법이 있습니다.

## 6. 외부 채널과의 관계를 정한다

야놀자·여기어때·에어비앤비를 함께 쓰신다면 재고가 두 곳에 존재하게 됩니다. 여기를 정리하지 않으면 중복 예약이 홈페이지가 아니라 채널 사이에서 발생합니다.

- [ ] 홈페이지와 외부 채널에 같은 객실을 동시에 올릴 것인가
- [ ] 올린다면 재고를 나눠 배정할 것인가, 실시간으로 동기화할 것인가
- [ ] 채널별 요금을 다르게 가져갈 것인가 (홈페이지 직예약 할인)
- [ ] 채널에서 들어온 예약을 관리자에 수기로 입력할 사람이 있는가

> 채널 자동 연동(채널 매니저)은 각 플랫폼의 제휴·API 승인이 선행됩니다. **초기에는 관리자에서 날짜를 막는 수기 방식으로 시작하고, 물량이 늘면 연동을 검토**하는 순서를 권합니다.

## 7. 예약자 정보와 개인정보

- [ ] 예약 시 어떤 정보를 받을 것인가 (이름·연락처·차량번호·인원)
- [ ] 개인정보 수집·이용 동의를 예약 화면에서 받는가
- [ ] 예약 정보를 언제까지 보관하고 언제 파기하는가
- [ ] 문자·알림톡 발송에 필요한 수신 동의를 별도로 받는가
- [ ] 관리자 계정을 여러 명이 쓴다면 누가 무엇까지 볼 수 있는가

> 알림톡은 카카오 채널 개설 → 발신프로필 등록 → **문구별 사전 심사**를 거칩니다. 예약 확정·취소 안내 문구를 미리 정해 두시면 심사 기간을 줄일 수 있습니다.

## 8. 도입 전 마지막 확인

- [ ] 객실·요금표를 날짜 기준으로 채워봤는가
- [ ] 취소 시점별 환급률 표를 만들었는가
- [ ] 성수기 기간을 약관 문구로 적어봤는가
- [ ] PG 심사 기간을 오픈 일정에 넣었는가
- [ ] 외부 채널 재고 처리 방식을 정했는가
- [ ] 관리자를 누가 맡고, 예약 확인을 하루 몇 번 할 것인가
